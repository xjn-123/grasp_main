# 最终选型总结：检测 + 精定位（免训练）推荐顺序与搭建方案

> **本文的定位**：前几份文档做的是"地毯式清单"（有哪些模型、各自什么水平）。本文做**收敛**——按你的实际约束选出模型、排出先后、给出每个的简要搭建步骤。
>
> **硬件前提：RGB-D。** 两条定位路线都使用深度图（不是纯 RGB）。因此本总结的排序按"有深度可用"来做，与纯 RGB 榜单的排序有三处不同，见 4.0。
>
> **先钉死一个定义（本次修订的关键）**：
>
> | 层 | 是否训练 | 说明 |
> |---|---|---|
> | **检测层**（在彩色图上框出/抠出物体） | **要训练** | 用 CAD 造合成数据训练 YOLO11-seg；或换开放词汇模型免训 |
> | **快速定位层**（路线 A，10–80 ms） | **要训练** | CAD 自动生成训练样本 → 训练位姿网络；换物体要重训 |
> | **精定位层**（路线 B，0.5–6 s） | **免训练** | 换物体只换 CAD、重新渲染模板，不碰任何权重、不做梯度下降 |
>
> 所以"免训练"这个词的准确含义是：**精定位这一层的网络是通用的、预训练好的，换物体时不做任何权重更新**。它不承诺"整个系统都不要数据"。
>
> 两条定位路线**并列**，共用检测层与深度图：默认走 A（快），新零件刚到、A 还没训好时走 B（免训）；B 还能离线给 A 打标签。

## 0. 结论先行

### 0.1 最终推荐组合

两条路线**并列**，共用同一个检测层：

```
                      ┌──────────────────────────────────────┐
                      │   CAD 模型（一份，标准化到米）        │
                      └───────────────┬──────────────────────┘
                                      │
                    ┌─────────────────┴─────────────────┐
                    ↓                                   ↓
        【路线 A · 快速定位】                 【路线 B · 精定位】
         BlenderProc 造 1–2 万张              渲染 200–800 张模板
              ↓                                    ↓
         训练（几小时）                      onboarding（几分钟）
              ↓                                    ↓
         YOLO11-pose → PnP                     FoundPose 检索 + 匹配
              ↓                                    ↓
          10–80 ms/帧                          0.5–6 s/帧
              ↓                                    ↓
         换物体要重训                          换物体只换 CAD
                    └─────────────────┬─────────────────┘
                                      ↓
                          共用检测层：YOLO11-seg 掩膜
                          （用同一份 CAD 造合成数据训练）
```

真机一帧的调用方式（**两条路线都吃深度图**）：

```
真机 RGB ──┐
           ├─→ 对齐的 RGB-D（深度单位：米，float32）
真机 Depth ┘
   │
   ├─[检测层] YOLO11-seg ──→ 掩膜 mask
   │                            │
   │            ┌───────────────┴───────────────┐
   │            ↓                               ↓
   │     路线 A：裁剪图 → 关键点 → PnP      路线 B：裁剪图 → FoundPose
   │            ↓                               ↓
   │     深度 ICP 精修（几十 ms）          深度 ICP 精修（几十 ms）
   │            ↓                               ↓
   │      10–80 ms/帧                       0.5–6 s/帧
   │      换物体要重训                      换物体只换 CAD
   │
   └─ 默认走 A；新零件刚到、A 还没训好时走 B

掩膜 ∩ 深度 → 物体点云，是两条路线共用的预处理步骤
```

**深度质量是两条路线的共同天花板**——这一点把前面那份 `Fast-FoundationStereo_落地方案.md` 从"可选优化"变成了关键路径上的一环。

### 0.2 排序总表

| 层 | 名次 | 模型 | 一句话理由 |
|---|---|---|---|
| **检测** | 1 | **YOLO11-seg** | 一份 CAD 两种用途，掩膜质量可控、15–30 ms |
| | 2 | YOLOE | 实在不想训就用它，改提示词即可 |
| | 3 | CNOS | 评估/对齐论文数字时用 |
| **快速定位** | 1 | **YOLO11-pose + solvePnP + 深度 ICP** | 标签从 CAD 自动投影生成，一天出结果，10–25 ms |
| | 2 | **ZebraPose** | 工业级精度（Mean AR 0.752），合成数据即可，深度只用于精修 |
| | 3 | GeoTransformer | 学习式点云配准（神经网络），直接吃深度点云 |
| | 4 | DLTPose / PFA | 精度最高（0.797），工程量大 |

### 0.3 四条最重要的提醒

1. **Co-op 的论文数字最好，但你拿不到代码。** 我核实了 NAVER LABS 官方项目页：只有论文和 arXiv 链接，**没有 GitHub 仓库，也未发布权重或安装说明**。论文里它只粗估就 58.4 AR（FoundPose 37.3、GigaPose 27.6），确实是最优解——但落不了地。所以排序里它不占位，只作为"未来开源时立刻换"的观察项。

2. **FoundPose 的许可是 CC BY-NC 4.0（非商业）。** 如果你的抓取系统要商用或交付客户，这一条是硬伤，必须换 FoundationPose 或自研。这条很多人会漏。

3. **FoundPose 开源版只含粗位姿，没有 refinement。** 官方 README 明说"we provide the coarse pose estimation pipeline without the featuremetric refinement stage"。也就是说它单独用就是 37.3 那一档。**但你既然有深度图，最划算的补救不是装 MegaPose，而是接一个几十毫秒的深度 ICP**——粗位姿通常已经好到足够让 ICP 收敛。

4. **两条路线都依赖深度 → 深度质量 = 共同天花板。** 先花半天做深度基准测试（平面靶标，0.3/0.5/1.0/1.5 m 的 RMS 与空洞率），再决定要不要投入后面几周。验收参考：0.5 m 处 RMS < 2 mm、1.0 m 处 RMS < 8 mm、有效率 > 90%。

## 1. 免训练免的是哪一层

把一条位姿流水线拆成四步，"训练"这件事的分布是这样的：

| 步骤 | 干什么 | 换一个新物体时要做什么 | 算不算训练 |
|---|---|---|---|
| ① 检测/分割 | 在图上找到物体、抠出掩膜 | **重新训练检测器**（或换提示词） | **算**（若用 YOLO11-seg） |
| ② Onboarding | 渲染 CAD 多视角模板、提取特征、建表示 | 重跑一次，几分钟 | **不算**（无梯度下降） |
| ③ 粗位姿 | 裁剪图与模板比对 → 初始位姿 | 什么都不做 | 免 |
| ④ Refine | 渲染-比对迭代精修 | 什么都不做 | 免 |

**你要的"精定位免训练"= ③④ 免，② 只需重跑。** ①是否免取决于你选哪个检测器。

对照一下两条路线，"训练"这件事的分布是：

| 环节 | 路线 A · 快速定位 | 路线 B · 精定位 |
|---|---|---|
| 检测层 | 要训练 | 要训练（同一份合成数据） |
| 位姿网络 | **要训练**（换物体重训，几小时） | **免**（通用预训练网络） |
| Onboarding | 无此环节 | 渲染模板 + 提特征，几分钟 |
| 每帧速度 | 10–80 ms | 0.5–6 s |
| 换一个零件的成本 | 造数据 + 训练 ≈ 几小时 | 重跑 onboarding ≈ 几分钟 |

所以两条路线的取舍很直白：**用"每次换型几小时训练"换"每帧快 10–100 倍"。** 零件种类固定、批量大 → 走 A；换型频繁、来不及训 → 走 B。

行业里对 ② 有明确的时间标准：**BOP 2024 规定 onboarding 必须在单张 GPU 上 5 分钟内完成**（渲染一张 BlenderProc 图按 2 秒计）。你的系统也该按这个量级设计——换一个零件 5 分钟内能上线，才算"换型免训"。

| 方法 | onboarding 要渲染多少模板 |
|---|---|
| MegaPose | 9 万+ |
| FoundPose | 约 800 |
| **Co-op** | **42**（这是它的核心创新之一） |
| GigaPose | 较少 |

模板数直接决定 onboarding 时间。FoundPose 800 张 × 2 s ≈ 27 分钟——**已经超过 BOP 的 5 分钟标准**，所以实际部署要降模板数或降分辨率，这一点写在第 7 节坑表里。

## 2. 检测层推荐顺序（要训练）

### 2.1 排序与对比

| 名次 | 模型 | 换物体 | 速度（GTX 1650） | 依赖 | 备注 |
|---|---|---|---|---|---|
| 1 | **YOLO11-seg** | 重新训练（几小时） | 15–30 ms | ultralytics，Windows 原生 | 官方名不带 v，"YOLOv11"是社区叫错的 |
| 2 | **YOLOE** | **改提示词即可** | 25–40 ms | ultralytics 主包已含 | 开放词汇，带实例分割 |
| 3 | **CNOS** | 免（给 CAD 渲染模板比对） | 200–600 ms | FastSAM + DINOv2，纯 torch | BOP 官方默认检测 |
| 4 | Grounding DINO + SAM | 改提示词 | 200–500 ms + SAM | 纯 torch | 框准，但无掩膜需配 SAM |
| 5 | SAM 3 / DINO-X | 改提示词 | 慢 | — | 分割质量最好，速度换精度 |

### 2.2 为什么首选 YOLO11-seg 而不是 CNOS

CNOS 是 BOP 官方默认检测，学术对比时用它最公平。但工业上我更推荐 YOLO11-seg：

- 你**已经要为精定位准备 CAD 网格**，用它跑 BlenderProc 造合成数据是顺手的事，一份 CAD 两种用途。
- YOLO11-seg 在固定零件种类上，掩膜质量和速度都远好于 CNOS（15 ms vs 数百 ms）。
- CNOS 的价值在于"新物体零成本"——但你的精定位层已经用了几分钟 onboarding，检测层再省这点时间的边际收益不大。

**真正该用 CNOS 的场景**：你在跟论文数字对齐、或者零件种类极其频繁变动（每天换好几个）时。

### 2.3 YOLO11-seg 的简要搭建

```bash
# 1) 装环境（Windows 原生）
pip install ultralytics opencv-python

# 2) 用 BlenderProc 造数据（跨平台，Windows 可跑）
pip install blenderproc
# 写 gen_synth.py：导入 CAD → 域随机化 → bproc.writer.write_bop() 导出
# 同时导出分割掩膜（转成 YOLO-seg 的 txt 多边形标签）

# 3) 训练
yolo segment train data=parts.yaml model=yolo11s-seg.pt \
     epochs=100 imgsz=640 batch=8 amp=True device=0

# 4) 导出（可选，CPU/边缘部署时）
yolo export model=runs/segment/train/weights/best.pt format=onnx
```

**决定成败的是域随机化，不是网络结构。** 六条硬要求：

| 项 | 要求 |
|---|---|
| HDRI 背景 | ≥ 50 张 |
| 光照 | 数量、位置、强度、色温全随机 |
| 材质 | 金属/塑料/粗糙/反光随机（零件材质固定则至少随机背景材质） |
| 遮挡 | 随机撒干扰物体 |
| 噪声 | 高斯噪声、运动模糊、色差 |
| 真实图 | 混 10–20% 真机图（哪怕没标签也能做背景替换） |

不做域随机化，合成数据训出来的模型到真机上 mAP 会直接崩——这是这个领域最常见的翻车点。

### 2.4 YOLOE 的两个已核实坑

- 首次 `set_classes()` 会**联网下载 TorchScript 文本编码器**（YOLOE-26 约 254 MB）。离线部署前必须先跑一次，或用 `save_prompt_embeddings()` 固化。
- 导出 ONNX/TensorRT 后**类别被烘死**，改类别要重新从 `.pt` 导出。

## 3. 快速定位层推荐顺序（CAD 造样本训练，每帧快）

**这是"路线 A"**：用 CAD 脚本自动生成训练样本 → 训练一个位姿网络 → 每帧 10–80 ms。它与精定位的唯一区别是**换物体要重新训练**（几小时），换来的速度是 10–100 倍。

**前提（本次新增）：两条路线都用 RGB-D。** 深度在这条路线里有三种用法，按性价比排：

| 用法 | 说明 | 推荐度 |
|---|---|---|
| ① 给网络当输入通道 | 部分网络支持 RGB-D 输入（GeoTransformer 类、FreeZe 类） | 中 |
| ② **refine 阶段做 ICP 精修** | 网络出粗位姿后，用深度点云与 CAD 点云做 ICP 收敛 | **高，几乎免费** |
| ③ 掩膜 ∩ 深度 → 裁剪出"只属于这个物体"的点云 | 把背景点剔干净，是②能做好的前提 | **必做** |

注意 ② 是模型管线的一部分（FreeZeV2.1 冠军方案本身就含深度 ICP refine），不是"退回纯几何算法"——你之前定的"两条路线都用模型"这个约束仍然成立。

### 3.1 排序表

| 名次 | 模型 | 类型 | Mean AR | 速度 | 用深度 | 工程量 |
|---|---|---|---|---|---|---|
| 1 | **YOLO11-pose 关键点 + solvePnP** | 关键点 + PnP | 中 | **10–25 ms** | 可选（ICP 精修） | **低，一天出结果** |
| 2 | **ZebraPose** | 分层表面编码 → 稠密 2D-3D 对应 → PnP | **0.752** | 30–80 ms | 否（纯 RGB 即可） | 高 |
| 3 | **GeoTransformer** | 学习式点云配准（神经网络，SVD 闭式解） | 高 | 30–80 ms | **是** | 高 |
| 4 | DLTPose / PFA | 稠密表面点 + DLT / 逐像素投票 | **0.797** | 中 | 否 | 高 |
| 5 | RCVPose / SurfEmb | 反向对应验证 / 连续表面嵌入 | 0.749 / 0.760 | 中 | 否 | 高 |
| 6 | YOLO6DPose / EfficientPose | 端到端回归 6 个数 | 中低 | 快 | 否 | **最低** |
| — | CosyPose / GDR-Net / PVNet | 上一代主力 | 0.714 / — / 0.638 | 中 | 否 | 中 |

**端到端回归为什么排最后**：直接回归旋转是个病态问题——旋转表示本身不连续（比如 179° 和 -179° 在数值上离得很远，姿态却几乎一样）。所以回归 6 个数的方案精度天然吃亏，只有在"精度要求不高、就想省事"时才用。

### 3.2 第 1 名搭建：YOLO11-pose 关键点 + PnP

**为什么排第一**：标签完全由 CAD 自动生成，不需要任何人工标注，一天能跑通，而且精度对多数抓取场景够用。

**第一步：在 CAD 上标一次 3D 关键点**（N ≥ 6，尽量不共面、分布在整个物体上）。

**第二步：渲染时用已知位姿把 3D 点投影成 2D 标签**——这是整个方案的核心技巧：

```python
import numpy as np

K = np.array([[fx, 0, cx],
              [0, fy, cy],
              [0,  0,  1]])
T_cam_obj = ...          # 渲染时我们自己设定的位姿，因此已知
kpts3d = np.array([...]) # (N,3) CAD 上标好的关键点，单位米

kpts_cam = (T_cam_obj[:3, :3] @ kpts3d.T).T + T_cam_obj[:3, 3]
uv = (K @ kpts_cam.T).T
uv = uv[:, :2] / uv[:, 2:3]   # 归一化 → 这张图的 2D 关键点标签
```

**第三步：训练与推理**

```bash
# 训练（BlenderProc 渲染时同步写出 YOLO-pose 格式的 txt 标签）
yolo pose train data=parts_pose.yaml model=yolo11s-pose.pt \
     epochs=100 imgsz=640 batch=8 amp=True device=0

# 推理端反解位姿
retval, rvec, tvec, inliers = cv2.solvePnPRansac(
    kpts3d, uv_pred, K, None,
    reprojectionError=8.0, confidence=0.999, flags=cv2.SOLVEPNP_EPNP)
R, _ = cv2.Rodrigues(rvec)
T_cam_obj = np.eye(4)
T_cam_obj[:3, :3] = R
T_cam_obj[:3, 3]  = tvec.ravel()
```

**第四步（有深度时必做）：ICP 精修**

```python
import open3d as o3d
# 用掩膜 ∩ 深度裁剪出物体点云 → 用 T_cam_obj 作初值 → ICP 到 CAD 采样点云
pcd_scene = mask_crop_pointcloud(rgb, depth, K, mask)     # 真机观测
pcd_model = o3d.geometry.PointCloud()
pcd_model.points = o3d.utility.Vector3dVector(model_xyz)  # CAD 采样
T_refine = o3d.pipelines.registration.registration_icp(
    pcd_scene, pcd_model, max_correspondence_distance=0.005,
    init=T_cam_obj,
    estimation_method=o3d.pipelines.registration.TransformationEstimationPointToPlane())
T_cam_obj = T_refine.transformation
```

用 Point-to-Plane（不是 Point-to-Point），收敛更快更准；`max_correspondence_distance` 取物体尺寸的 1–2%。

### 3.3 第 2 名搭建：ZebraPose

工业级精度，纯 RGB 就能跑（深度只用于 refine），训练数据可以 100% 合成。

- **核心是把物体表面离散成小格**：网络对每个前景像素预测"属于哪个格 + 格内偏移"，于是得到稠密的 2D-3D 对应，再用 PnP/RANSAC 闭式解出位姿。
- **训练样本同样由脚本生成**：渲染时输出每像素的格 ID 图和偏移图（BlenderProc 里用自定义 AOV / 材质索引实现）。
- **多阶段训练**（先粗后细），工程量比 YOLO-pose 高一个量级，约 2–4 周。
- 附带好处：能输出物体的可见性掩码。

如果 YOLO11-pose 的精度不够抓取（平移 > 3 mm），就上这个。

### 3.4 一个省大钱的做法：用精定位给快速定位打标签

合成数据训的模型到真机崩，根因是**域差距**。既然你有精定位这条免训路线，就有了近乎零成本的标注器：

```
真机拍 300–500 张（不用标注）
   → 路线 B（FoundPose）逐张出位姿
   → 用位姿把 CAD 关键点投影回图像 = 自动标签
   → 用这批真机标签微调路线 A
```

这条闭环能同时解决两件事：域差距问题，以及"真机数据没标签"的问题。精定位慢不怕，它是离线跑的。

## 4. 精定位层推荐顺序（换 CAD 不重训）

**有深度图后，本层的排序相对上一版有三处调整**（见 4.0）。

### 4.0 深度可用带来的三点变化

1. **粗位姿之后可以免费接一个深度 ICP 精修。** 这是最划算的一步——FoundPose 单独只有 37.3 AR，但粗位姿已经足够好到让 ICP 收敛，补上这一步能显著拉近与"配 MegaPose refine（55.0）"的差距，而成本只是几十毫秒。**在你这套 RGB-D 系统里，FoundPose 的实际精度可以高于它纯 RGB 榜单的数字。**
2. **FoundationPose 排名上升。** 它原生支持 RGB-D，给深度时精度明显高于纯 RGB 模式。代价仍是必须编译 nvdiffrast + PyTorch3D（→ WSL2）。
3. **FreeZeV2.1 从"只做参考"变成可考虑项。** 它是 RGB-D 冠军（AR 82.1），你既然有深度，它的前置条件就满足了；但它要吃三路分割（SAM-6D + NIDS + CNOS）再做 NMS，工程量仍是最大的。

### 4.1 排序表（含可获取性、许可、依赖）

| 名次 | 模型 | 开源 | 许可 | 依赖 | 粗位姿 AR | 配 refine 后 | 耗时 | 吃深度 | Windows |
|---|---|---|---|---|---|---|---|---|---|
| 1 | **FoundPose**（+ 深度 ICP 精修） | 完整开源 | **CC BY-NC 4.0** | 纯 torch + 渲染器 | 37.3 | 55.0（+MegaPose） | 1.69 s / 6.39 s | **仅 ICP 阶段** | 可行 |
| 2 | **FoundationPose** | 开源（NVlabs） | NVIDIA 源码许可 | **nvdiffrast + PyTorch3D + Eigen** | 粗+精一体 | 曾 BOP 第一 | 亚秒–数秒 | **是（RGB-D 原生）** | 需 WSL2 |
| 3 | FreeZeV2.1 | 开源 | 研究许可 | 重（三路分割） | — | 82.1（BOP 2024 冠军） | 中 | **是（RGB-D）** | 困难 |
| 4 | GigaPose + MegaPose | 开源 | 研究许可 | **PyTorch3D** | 27.6 | 54.7（+MegaPose） | **0.38 s** / 2.30 s | 否 | 需 WSL2 |
| 5 | OPFormer / PicoPose | 开源 | 研究许可 | 纯 torch | — | 0.525 / 0.492（LM-O） | **0.49 / 0.66 s** | 否 | 可行 |
| — | Co-op | **未开源** | — | CroCo 预训练 | **58.4** | 64.0（1 假设）/ 65.7（5 假设） | 0.98 / 1.85 s | 否 | 不可得 |

> AR = Average Recall，BOP 标准指标，越高越好。表中 AR 为 BOP 七数据集平均（Co-op、FoundPose、GigaPose、MegaPose、GenFlow 对比）与 LM-O 榜单（OPFormer/PicoPose）混合，跨数据集不可直接横比，仅作量级参考。

### 4.2 第 1 名：FoundPose（首选，先跑通这个）

**为什么排第一**：官方完整开源（含代码、模板、表示、推理输出示例）、零权重、纯 torch + DINOv2、你这台机器能跑。它是"最快拿到第一个真实位姿数字"的路径。

**官方四步流水线**（已核实 README）：

```bash
# 0) 环境
git clone --recurse-submodules https://github.com/facebookresearch/foundpose
cd foundpose
conda env create -f conda_foundpose_gpu.yaml
conda activate foundpose_gpu

# 必须配置环境变量（写在 $CONDA_PREFIX/etc/conda/activate.d/env_vars.sh）
export REPO_PATH=/path/to/foundpose
export BOP_PATH=/path/to/bop/datasets
export PYTHONPATH=$REPO_PATH:$REPO_PATH/external/bop_toolkit:$REPO_PATH/external/dinov2

# 1) 渲染模板
python scripts/gen_templates.py --opts-path configs/gen_templates/lmo.json

# 2) 建立物体表示（DINOv2 特征 + BoW）
python scripts/gen_repre.py --opts-path configs/gen_repre/lmo.json

# 3) 推理
python scripts/infer.py --opts-path configs/infer/lmo.json

# 4) 生成 BOP 提交文件 / 评估

```

**官方现成产物**（省去渲染，先验证环境用）：

```
https://huggingface.co/datasets/evinpinar/foundpose/resolve/main/templates.zip
https://huggingface.co/datasets/evinpinar/foundpose/resolve/main/object_repre.zip
https://huggingface.co/datasets/evinpinar/foundpose/resolve/main/inference.zip
```

**接入你自己的物体要做三件事**：

1. 按 BOP 目录结构放你的 CAD：`$BOP_PATH/<your_ds>/models/obj_000001.ply`，**单位必须是米**。
2. 写一份自己的 `configs/gen_templates/<your_ds>.json`（照抄 `lmo.json` 改路径和相机内参）。
3. 把检测结果写成 BOP detection 格式：
   ```
   $BOP_PATH/detections/cnos-fastsam/cnos-fastsam_<your_ds>_test.json
   ```
   格式是 `[{"scene_id":..,"im_id":..,"obj_id":..,"score":..,"bbox":[...],"segmentation":{...}}, ...]`。
   **你用 YOLO11-seg 的话，就是在这里把掩膜转换成这个 JSON** —— 这是检测层和精定位层的唯一接口。

**已知限制（务必记住）**：

- 开源版**没有 refinement**。要精度必须外接 MegaPose 或 FoundationPose。
- 开源版用的渲染器和论文不同，官方自己给出对照：LMO 发表 34.0 / 复现 33.7，TUD-L 42.7 / 40.7（ViT-S）。差距很小，可接受。
- **许可 CC BY-NC 4.0**：非商业。商用项目请改走 FoundationPose。

### 4.3 第 2 名：FoundationPose（有深度时升到第 2）

NVlabs 官方开源，`git clone https://github.com/NVlabs/FoundationPose`。

```bash
# 方式一：Docker（官方推荐）
cd docker/
docker pull wenbowen123/foundationpose
docker tag wenbowen123/foundationpose foundationpose
bash docker/run_container.sh
# 首次进容器需要编译扩展
bash build_all.sh

# 方式二：conda（官方标注 experimental）
conda create -n foundationpose python=3.9
conda activate foundationpose
# 装 Eigen 3.4.0（必须）
pip install -r requirements.txt
pip install git+https://github.com/NVlabs/nvdiffrast
pip install --no-build-isolation git+https://github.com/facebookresearch/pytorch3d.git
```

权重放 `weights/`（仓库 README 里的 Google Drive 链接），测试数据放 `demo_data/`。

**为什么有深度就该选它**：它原生支持 RGB-D 与 RGB 两种模式，**给深度时精度明显高于纯 RGB 模式**，而且它是粗位姿 + refine 一体的完整管线，不像 FoundPose 那样缺一个精修环节。代价是必须编译 nvdiffrast + PyTorch3D → 这是把你推向 WSL2 的主要原因。

**定位要搞清楚**：在 BOP unseen 榜单里它经常是当 refine 器出现的（「GigaPose/FoundPose 出粗位姿 → FoundationPose 精修」），但它是少数能单独跑完整流程的方案之一。

### 4.4 第 3 名：FreeZeV2.1（RGB-D 精度天花板）

- BOP 2024 model-based 6D localization **冠军，AR 82.1**，只比"已见物体"最佳方法低 3.5。
- **本来就要求 RGB-D**，你既然有深度图，它的前置条件就满足了——这是它在本次排序里上升的原因。
- 特征 = DINOv2 的 2D 视觉特征 **拼接** GeDi 的 3D 几何特征，都从渲染图上提取并聚合到物体表面；用 RANSAC 拟合 3D-3D 对应，再接**深度 ICP + 对称感知 refinement**。
- 吃三路分割（SAM-6D + NIDS + CNOS），对每个掩膜估一个位姿和置信度，最后 NMS 保留最好的。
- **代价**：依赖多、工程量大，只建议作为"精度上限参考"或在精度确实不够时攻坚。

### 4.5 第 4 名：GigaPose + MegaPose（纯 RGB，速度最快）

- GigaPose 单独粗估只要 **0.384 s**，配 MegaPose refine 后 54.7 AR @ 2.30 s。
- 依赖 **PyTorch3D**，官方预编译 wheel 只到 `py39_cu118_pyt200`，与 torch 2.6 + cu124 不匹配，**只能源码编译** → 需 WSL2。
- 换型流程与 FoundPose 相同：渲染模板 → 提特征 → 推理，**同样不训练**。
- 纯 RGB，吃不到你的深度图——这是它排在 FoundationPose 之后的原因。

### 4.6 第 5 名：OPFormer / PicoPose（最快，但吃不到深度）

榜单上最快的两个：OPFormer 0.49 s（AR 0.525，LM-O）、PicoPose-1hyp 0.66 s（AR 0.492）。纯 torch，Windows 可跑，且不需要 WSL2。如果 0.5–2 s 的精度够抓取，这两个是最省事的终点——但它们同样用不上深度图。

### 4.7 Co-op：数字最强，但拿不到

CVPR 2025，NAVER LABS。论文数据确实碾压同级：

| 方法 | 粗位姿 AR | 粗位姿耗时 | +refine（1 假设） |
|---|---|---|---|
| MegaPose | 20.8 | 15.47 s | 50.9 @ 31.7 s |
| GenFlow | 23.5 | 3.84 s | 55.7 @ 10.6 s |
| GigaPose | 27.6 | **0.38 s** | 54.7 @ 2.30 s |
| FoundPose | 37.3 | 1.69 s | 55.0 @ 6.39 s |
| **Co-op** | **58.4** | **0.98 s** | **64.0 @ 1.85 s** |
| **Co-op（5 假设）** | — | — | **65.7 @ 4.19 s** |

它只用 **42 个模板**（FoundPose 800、MegaPose 9 万+），靠"patch 分类 + 偏移回归"的混合表示 + CroCo 预训练。

**但官方项目页没有代码仓库、没有权重、没有安装说明。** 网上有第三方复现，不建议作为生产依赖。列入"开源即评估"的观察清单。

## 5. 三层之间的接线方案

### 5.1 唯一接口：BOP detection JSON

两层之间只传一个东西：**物体的掩膜（或框）+ 物体 ID**。不要传特征、不要传中间张量。

```python
# detect_to_bop.py：YOLO11-seg 输出 → BOP detection 格式
import json, numpy as np
from ultralytics import YOLO

model = YOLO("runs/segment/train/weights/best.pt")

def to_bop_detections(rgb, scene_id=1, im_id=1, obj_id=1):
    res = model(rgb, verbose=False)[0]
    out = []
    if res.masks is None:
        return out
    for score, box, mask in zip(res.boxes.conf, res.boxes.xyxy, res.masks.xy):
        out.append({
            "scene_id": scene_id,
            "im_id": im_id,
            "obj_id": int(obj_id),
            "score": float(score),
            "bbox": [float(v) for v in box],                 # [x1,y1,x2,y2]
            "segmentation": {"counts": rle_encode(mask),     # 或直接用 polygon
                             "size": list(rgb.shape[:2])},
        })
    return out

with open("detections/yolo-seg/results.json", "w") as f:
    json.dump(to_bop_detections(rgb), f)
```

### 5.2 统一接口（两条定位路线共用一个签名）

```python
class PoseEstimator:
    """下游只认 T_cam_obj，换实现不动业务代码。"""

    def estimate(self, rgb, depth, K, obj_id) -> tuple[np.ndarray, float]:
        """返回 (T_cam_obj (4,4) float64, 置信度)。"""
        raise NotImplementedError


class FoundPoseEstimator(PoseEstimator):   # 精定位：换 CAD 不重训
    ...

class FastEstimator(PoseEstimator):        # 快速定位：YOLO11-pose + PnP
    ...
```

坐标约定写在注释里：**`T_a_b` = 从 b 坐标系到 a 坐标系的变换**。精定位输出统一为 `T_cam_obj`。

### 5.3 深度图的接线（两条路线共用）

两条路线都要吃深度，所以深度必须**和彩色图像素级对齐**，并且单位统一。约定：

| 约定 | 值 |
|---|---|
| 深度图 | 与彩色图同分辨率、已对齐到彩色相机坐标系 |
| 存储 | `float32`，单位**米** |
| 无效值 | `0` 或 `NaN` 表示无深度（不是"距离为 0"） |
| 内参 | `K = [fx, fy, cx, cy]`，与深度图分辨率一致 |

如果你走 FFS 自研双目那条路（见 `Fast-FoundationStereo_落地方案.md`），让深度节点直接输出**米制 float32**，把 `depth_scale` 固定为 1.0，下游就不需要再做单位换算。

**验证对齐的方法**（必做）：在彩色图上点一个 AprilTag 角点，读该像素的深度值，与用 `T_cam_tag` 算出的 tag 平面深度对比，差应 < 几毫米。差得越多说明对齐越有问题。

## 6. 评估：怎么知道准不准

不贴 AprilTag 就没真值，这是最麻烦的一环。解法：**评估阶段临时贴一个 AprilTag 当真值，量化完撕掉**——这不违反你的生产约束，只用于标定评估系统本身。

```python
# eval_pose.py 思路
# 1) 临时在物体上贴 AprilTag，先用 AprilTag 求 T_cam_tag（精度 <1 mm，当真值）
# 2) 手眼标定 T_tag_obj（贴的时候量一次，或用 CAD 对齐）
# 3) 真值 T_cam_obj_gt = T_cam_tag @ T_tag_obj
# 4) 估计值 T_cam_obj_est 来自精定位
# 5) 算误差：
#    平移误差 = ||t_est - t_gt||
#    旋转误差 = arccos((trace(R_est @ R_gt.T) - 1) / 2)   ← 记得 np.clip(x, -1, 1)
#    对称物体用 ADD-S（取所有对称变换里最小的距离）
```

**验收参考线**（刚体、纹理尚可、遮挡 < 30%）：

| 指标 | 快速定位 | 精定位 |
|---|---|---|
| 平移误差 | 2–5 mm | 1–3 mm |
| 旋转误差 | 2–5° | 1–3° |

反光件、纯黑件会显著变差，这是物理限制，不是调参能救的。

## 7. 落地时间表

| 周次 | 任务 | 产出 | 环境 |
|---|---|---|---|
| **第 0 周** | **深度质量基准**：平面靶标测 0.3/0.5/1.0/1.5 m 的 RMS 与空洞率；验证深度-彩色对齐 | 一张"误差—距离"表 | Windows |
| **第 1 周** | `cad_prep.py` + FoundPose 环境 + 用官方 LM-O 产物跑通推理 | 环境可用、理解四步流水线 | Windows |
| **第 2 周** | 导入自己的 CAD → 渲染模板 → onboarding → 出第一个位姿 + **接深度 ICP 精修** | **第一个真实位姿数字** | Windows |
| **第 3 周** | BlenderProc 合成数据 + 训练 YOLO11-seg + 接 `detect_to_bop.py` | 检测+精定位全链路跑通 | Windows |
| **第 4 周** | **路线 A**：CAD 标关键点 → 自动生成标签 → 训练 YOLO11-pose → PnP → ICP 精修 | 快速定位基线，10–25 ms | Windows |
| **第 5 周** | 临时贴 AprilTag 取真值，量化两条路线；写 `estimate.py` 统一接口 | 误差报告 + 可切换的接口 | Windows |
| **按需** | 精度不够 → 装 WSL2 上 FoundationPose（RGB-D）或 FreeZeV2.1 | 精度上限 | WSL2 |

**第 0 周不能跳**：两条路线都吃深度图，深度质量就是它们的共同天花板。如果 1 m 处 RMS 已经到 8 mm，那 ICP 精修和 RGB-D 精定位都救不回来，得先解决深度（这正是前面那份 FFS 落地方案的用武之地）。

**第 5 周是关键分叉点**：如果 FoundPose + 深度 ICP 这类纯 torch 方案给出的精度够抓取（多数场景平移 2–3 mm 足够），**你就永远不需要装 WSL2**。

## 8. 坑与对策

| # | 现象 | 根因 | 对策 |
|---|---|---|---|
| 1 | 商用交付被法务拦下 | **FoundPose 是 CC BY-NC 4.0** | 商用项目直接改用 FoundationPose 或自研 |
| 2 | 单独用 FoundPose 精度只有 37 AR 档 | 开源版不含 refinement | 外接 MegaPose / FoundationPose 做 refine |
| 3 | BOP 渲染器在 Windows 编译失败 | 依赖 OpenGL 上下文 | 用 BlenderProc 渲染模板，绕过官方渲染器 |
| 4 | onboarding 超过 5 分钟 | FoundPose 要 800 张模板 × 2 s | 降模板数到 200–300、降分辨率、批量并行 |
| 5 | 位姿平移差 1000 倍 | CAD 是毫米 | 加载后断言 `mesh.extents` 在合理米制范围 |
| 6 | 无纹理金属件匹配不到 | 用了 DINOv2 最后一层 | FoundPose 关键设计：**必须用中间层（第 18 层）** |
| 7 | 合成数据训的模型真机崩 | 域随机化不足 | HDRI ≥50、光照/材质/遮挡/噪声全随机，混 10–20% 真实图 |
| 8 | 检测结果质量决定一切 | 精定位吃的是裁剪图 | 掩膜必须干净；对比 YOLO-seg / CNOS / SAM 三个分割源 |
| 9 | 对称物体位姿跳变 | 旋转多解 | CAD 阶段定参考方向；用 ADD-S 指标；对称感知 refine |
| 10 | 没有真值无法评估 | 不贴 tag | 评估阶段临时贴 AprilTag，量化完撕掉 |
| 11 | 显存爆 | DINOv2 ViT-L 在 4 GB 卡上吃力 | 用 ViT-S/14 或 ViT-B/14；缩小裁剪图 |
| 12 | 抓取节拍跟不上 | 精定位 0.5–6 s | 精定位只用于换型 onboarding 和离线打标签，在线走快速定位 |
| 13 | `arccos` 出 nan | 数值误差让 cos 略超 1 | `np.clip((trace-1)/2, -1.0, 1.0)` |
| 14 | 想用 Co-op 但找不到代码 | **官方未开源** | 用 FoundPose 起步，把 Co-op 列入观察清单 |
| 15 | **掩膜 ∩ 深度 取出的点云带背景** | 深度-彩色没对齐，或掩膜边缘膨胀 | 掩膜向内腐蚀 2–3 px；先做对齐验证（见 5.3） |
| 16 | **ICP 越配越歪** | 初值太差，超出收敛域 | ICP 只能精修不能救场：粗位姿误差应 < 物体尺寸的 10%；`max_correspondence_distance` 取尺寸 1–2% |
| 17 | 深度单位错，位姿差 1000 倍 | 深度图是毫米整数（uint16） | 统一转米制 float32；写断言检查中位数在 0.3–2.0 |
| 18 | 反光/透明件深度全是洞 | 物理限制 | 这两类件别指望深度，改走纯 RGB 的 FoundPose/GigaPose 分支 |
| 19 | ICP 用 Point-to-Point 收敛慢 | 法线信息没利用 | 改 `TransformationEstimationPointToPlane()`，并先 `estimate_normals()` |

## 9. OS 与环境一句话结论

- **检测层（YOLO11-seg / YOLOE / CNOS）**：全 Windows 原生，你这台 i5-9300H / 8 GB / GTX 1650 完全够。
- **快速定位层（YOLO11-pose + PnP + Open3D ICP / ZebraPose）**：全 Windows 原生，训练也能跑（imgsz 640、batch 4–8、AMP）。
- **精定位首选 FoundPose**：纯 torch + 渲染器，**Windows 可行**（渲染环节用 BlenderProc 绕开 BOP 渲染器）；深度 ICP 精修走 Open3D，同样原生。
- **需要 WSL2 的唯一理由**：FoundationPose（nvdiffrast + PyTorch3D）、GigaPose / MegaPose / FreeZe（PyTorch3D）。注意这三个里前两个是"有深度时更该选"的，所以**WSL2 的概率比纯 RGB 方案时更高**。
- **你这台机器的性能预期**：榜单时间是 V100/A100 级的，1650 上粗估再乘 3–5 倍。FoundPose 1.69 s → 本机约 5–8 s；ICP 精修几十毫秒不受影响。抓取是"停稳→拍照→算→抓"，一次 1–3 帧，完全可接受。
- **内存是死结**：8 GB 跑"渲染模板 + 提特征"很紧张，渲染阶段降分辨率、分批。加内存到 16 GB 是这台机器唯一高性价比升级。
